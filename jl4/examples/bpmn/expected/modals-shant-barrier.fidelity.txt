  [F6] lossy — End_2
      This is where the whole group's breach arrives, however it arose and whoever caused it. The rule can be more specific: when a group obligation fails, the run works out which members failed and lists them — one entry for each failure, so a member who failed in two ways is named twice, and each entry says what that member owed and when it was due. BPMN has no way to put a list of parties on an end event, so this diagram records that the group breached and stops there.
      lost: which members breached, and how each of them did. This event looks the same whether one member fell short or all of them, so a reader of the diagram cannot tell who to chase; only the rule's own run can answer that.
  [P-DEADLINE-UNIT] advisory — Boundary_0
      Deadline ‘30’ carries no unit, because nothing in L4 fixes one — WITHIN is typed as a bare NUMBER (TypeCheck.hs) and the evaluator only ever adds it to an event timestamp. It is read here as days (P30D), following the commonest convention in the corpus, where event clocks are day counts (libraries/daydate.l4, `Day` AKA `Date to days`). A model stamping events in abstract ticks will need this edited.
      lost: certainty about the unit — if this model's clock is not days, the duration needs editing
