      `Claim`'s component `assessed grade` is declared `MAYBE OF Grade`, and DMN has no nullability marker -- tItemDefinition has no such flag -- so the emitted typeRef is the payload type's own. ADOPTED 2026-07-31 (R8-d'): NOTHING now lowers to FEEL `null` on the VALUE channel, so the conflation this note reports is a price paid deliberately and not an accident of the encoding. What buys it is that the artifact becomes EXECUTABLE where it was previously L4 source no engine could compile. `null` is still refused as an input ENTRY -- DMN 1.3 grammar rule 34 makes it a literal and rule 33's `simple literal` does not include it -- so no cell in this model asks an engine to test against it. No allowedValues or inputValues is emitted AT THIS ELEMENT, because DMN 7.3.3 makes allowedValues the COMPLETE range of values a type represents and `null` is not a legal S-FEEL endpoint -- and because that range is read through the typeRef, this element points at `Grade_optional`, a domain-free alias of `Grade`, rather than at `Grade` itself. Pointing at `Grade` would re-assert its complete range one hop on, and that range has no absent case in it, so an enforcing engine would reject the very NOTHING this type exists to allow
      lost: the distinction between an absent value and an undefined one, and -- at THIS element only -- engine-side validation of the values that ARE present: `Grade`'s domain is deliberately not asserted here, so a value outside it is no longer rejected at this site
