# miles-card — eight Singapore card reward programmes, from the issuers' own T&Cs

**Status (2026-09-21): being encoded.** This paragraph is corrected in the PR that lands the corpus.

An L4 encoding of the reward-programme terms and conditions of eight Singapore consumer cards, written so that "what does this transaction earn on this card?" is answered with the rate, the conditions, the clause relied on, and how far the answer can be trusted.
The subject sidecar is `etc/go/subjects/sg-miles-card/`; its `NOTES.md` carries the idiosyncrasies and the findings.
The design is in `mengwong/homelab` at `docs/projects/miles-card/SPEC-miles-card-l4-encoding.md` (canonical there).

**This is contract text, not law, and none of it is advice about what any card will pay.** Issuers say in each document that they may vary the terms without notice; the PDFs under `source/` are the snapshot of 2026-09-21.

## Regenerate layer 1

```
cd ~/src/smucclaw/dmnmd/languages/haskell
cabal run -v0 dmnmd -- -t l4 <this dir>/categorize.dmn.md   # emitted name f1 -> rename Categorize, prepend the header
```

The ditto-chain MCC tables inside two issuer modules were emitted by scripts, never hand-aligned, because a caret that is one column out fails silently by copying the wrong token.
The scripts are preserved beside the sources: `source/gen-womans-tables.py` (DBS Woman's cl.11 Tables 1 and 2) and `source/gen-hsbc-mcc.py` (HSBC cl.4.2 and cl.7 chains).
The UOB cl.34 block was generated the same way but its script was not preserved, so that block is now the source of record; regenerate it by following the HSBC script's shape.

## Run

```
l4 check miles-card.l4
l4 run   miles-card.l4
l4 catala miles-card.l4 -o /tmp/miles-card.catala_en && node etc/validate-catala.mjs /tmp/miles-card.catala_en
```

The third line is the gate the spec requires and the L4 exit code is not it (smucclaw/l4-ide#958).
