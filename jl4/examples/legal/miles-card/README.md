# miles-card — eight Singapore card reward programmes, from the issuers' own T&Cs

**Status (2026-09-21): being encoded.** This paragraph is corrected in the PR that lands the corpus.

An L4 encoding of the reward-programme terms and conditions of eight Singapore consumer cards, written so that "what does this transaction earn on this card?" is answered with the rate, the conditions, the clause relied on, and how far the answer can be trusted.
The subject sidecar is `etc/go/subjects/sg-miles-card/`; its `NOTES.md` carries the idiosyncrasies and the findings.
The design is in `mengwong/homelab` at `docs/projects/miles-card/SPEC-miles-card-l4-encoding.md` (canonical there).

**This is contract text, not law, and none of it is advice about what any card will pay.** Issuers say in each document that they may vary the terms without notice; the PDFs under `source/` are the snapshot of 2026-09-21.

## Layout

| path | what |
| --- | --- |
| `source/*.pdf`, `source/*.txt` | the ten issuer documents and their `pdftotext -layout` extracts; quote from the `.txt`, in paragraph mode (`perl -00ne 'print "----\n$_" if /PATTERN/' FILE`) |
| `source/source-bundle.json`, `source/external-modifications.json`, `source/fork-register.json` | the pipeline's P1, P2 and P4 deposits |
| `roadmap.json`, `COMPLETION.md` | P3.0 — every clause enumerated with its disposition; the coverage strip |
| `miles-card-domain.l4` | **the shared ontology**, `DECLARE` only. Every other module imports it and adds no nouns |
| `categorize.dmn.md` → `categorize.l4` | layer 1, the household's own merchant→category table (generated by dmnmd; edit the `.dmn.md`) |
| `dbs-yuu.l4`, `dbs-womans-world.l4`, `citi-rewards.l4`, `hsbc-revolution.l4`, `uob-ladys-solitaire.l4`, `posb-passion.l4`, `flat-cards.l4` | layer 2, one module per issuer document, each exporting `` `<card> earns on` card cardholder month txn `` |
| `miles-card.l4` | the composer: `` `the rate on` card cardholder month txn `` dispatches on the card |
| `miles-card-cases.l4` | assertions from the documents' own worked examples |
| `miles-card-disputed.l4` | cheat-sheet claims the primary text does not support, restated as `#ASSERT NOT` with both citations |
| `cheatsheet/cheatsheet-claims.l4` | the additional encoding `cheatsheet-2026-06`: the household cheat sheet's rows as assertions, written blind to the rule modules. Expected to fail in places; that is the acceptance test |
| `DEFEASIBILITY-SITES.md` | every place a native exception construct would have collapsed several guards into one rule |

## Regenerate layer 1

```
cd ~/src/smucclaw/dmnmd/languages/haskell
cabal run -v0 dmnmd -- -t l4 <this dir>/categorize.dmn.md   # emitted name f1 -> rename Categorize, prepend the header
```

## Run

```
l4 check miles-card.l4
l4 run   miles-card.l4
l4 catala miles-card.l4 -o /tmp/miles-card.catala_en && node etc/validate-catala.mjs /tmp/miles-card.catala_en
```

The third line is the gate the spec requires and the L4 exit code is not it (smucclaw/l4-ide#958).
