## 1. C1 — `l4 export FORMAT FILE` and `l4 import FORMAT FILE`

Every foreign notation L4 writes is a subcommand of `l4 export`, and every notation it reads is a
subcommand of `l4 import`. `l4 export --help` is the catalogue of targets.

| before 2026-09-24                                  | from 2026-09-24              |
| -------------------------------------------------- | ---------------------------- |
| `l4 export --to=dmn FILE`                          | `l4 export dmn FILE`         |
| `l4 export --to=dmn-md FILE` (or `dmnmd`)          | `l4 export dmn-md FILE`      |
| `l4 export --to=bpmn FILE`                         | `l4 export bpmn FILE`        |
| `l4 openfisca FILE`                                | `l4 export openfisca FILE`   |
| `l4 catala FILE`                                   | `l4 export catala FILE`      |
| `l4 blawx FILE [--scasp] [--roundtrip]`            | `l4 export blawx FILE [...]` |
| `l4 blawx --import FILE [--parse-only] [--reemit]` | `l4 import blawx FILE [...]` |
| `l4 docassemble FILE`                              | `l4 export docassemble FILE` |
| `l4 yscript FILE`                                  | `l4 export yscript FILE`     |

Stderr prefixes follow the command: `l4 export catala: …`, `l4 import blawx: …`. So do the
provenance headers written into generated files (`# Generated by \`l4 export openfisca\``).

**This reverses the ruling it replaces.** Until now the surface had two conventions side by side,
and `general-purpose-language-backends.md` Q7 said so in as many words: interchange notations
under `l4 export --to=` (DMN, BPMN), everything that compiles to a runnable artifact its own verb
(OpenFisca, Catala, Blawx, docassemble, yscript). That split was ruled in DOCASSEMBLE R1
(2026-08-16), restated as portfolio invariant I1, and followed by BLAWX R14 (2026-08-18), which
chose `l4 blawx --import` over "an `l4 import` family".

**Why it changed.** The split encoded what the output _is_, and a user looks for _where L4 can
send a module_. Whether an output is interchange or runnable is a property of each format, and it
is already visible where it matters: whether the format carries a fidelity report. Meanwhile the
count settles the surface question. There were five transpiler verbs beside eleven that are not
transpilers, with PROLEG (`jl4-proleg`, a two-way library with no command yet), the
logic-programming legs, RegelSpraak, TypeScript and Go in view. natural4's ~30
independently-registered modes are the cautionary precedent `LOGIC-PROGRAMMING-BACKENDS-SPEC.md`
§8.3 names; under one namespace the same growth is one `--help` screen, not thirty verbs.

**What this answers elsewhere.**

- **LP-R11** (`LOGIC-PROGRAMMING-BACKENDS-SPEC.md`): per-target formats under `l4 export`
  (`swipl`, `scasp`, `proleg`, `logical-english`, `ergo`), not an `l4 relational --target` verb.
- **Q7** (`general-purpose-language-backends.md`): `l4 export typescript` / `l4 export golang`.
  The collision Q7 raised was with a _top-level_ `l4 go`; a format name does not collide with it,
  but `golang` is still the unambiguous spelling.
- **DOCASSEMBLE R1** and **BLAWX R14** (CLI half): reversed; see each spec.
- **Portfolio I1** and **§6** "CLI verb surface": rewritten to cite this ruling.

## 2. C2 — what is an export

`export` is for writing a module out in a **foreign notation that another tool consumes**: an
interchange document (DMN, BPMN), a program in another rules language (OpenFisca, Catala,
yscript, Blawx's s(CASP)), or an interview (docassemble).

L4's own views and analyses of a file stay top-level verbs: `render`, `nlg`, `trace`,
`state-graph`, `lts`, `ast`, `verify`, and `batch`. They answer a question about the file for its
author, rather than hand it to another system.

**One deliberate exception, for now: Akoma Ntoso.** `l4 render --format akn` writes an OASIS
standard, which by the rule above makes it an export. It stays where it is for this change because
it is the one affected spelling that has already shipped from `main` (the `l4-ide-build-90`
release), and because `specs/research/LEOS-RESEARCH.md` measured that the AKN it writes is not
schema-valid yet (0 of 343 corpus renders pass the OASIS XSD). Moving it to `l4 export akn` belongs
with that repair, which will give it a fidelity report and an `xmllint` gate.

## 3. C3 — format names

A format is named after the **notation**, in lowercase, with a hyphen for a variant of the same
notation (`dmn-md`). Where the notation and its tool share a name (`openfisca`, `catala`,
`docassemble`), that name. Where they differ, the notation: `akn4eu`, not `leos`
(`LEOS-RESEARCH.md` §H).

There are no synonyms. `dmnmd` was accepted as a hidden synonym of `dmn-md` under `--to`; it is
not a format name.

## 4. C4 — a format's flags belong to that format

Each format is its own parser and offers only the flags it reads, so `l4 export dmn --help` lists
DMN's options and nothing else. The shared ones (`-o/--output`, and `--fidelity-report` /
`--fail-on` where the format has a fidelity report) are spelled the same everywhere.

This replaces `checkTargetFlags` in `L4.Cli.Export`, which refused at run time any of five flags
given to a `--to` target that does not read it. That refusal is now optparse's own
`Invalid option`, and the reasoning it enforced is kept on the parsers' Haddock
(`DMN-EXPORT-PROGRAM-MODEL-SPEC.md` §13.5 has the history of `--flavor`).

## 5. C5 — no aliases

The old spellings are removed, not deprecated. Meng, 2026-09-24: nothing in production uses them.
The transpiler verbs had reached `unstable` only; wave 3a was carrying them to `main` and was
amended in place to carry the new spellings instead.

**What an old spelling does now.** `l4 FILE` is the bare form of `l4 run FILE`, so an unrecognised
first word is read as a filename. `l4 blawx f.l4` therefore fails with `Invalid argument
\`f.l4'`rather than a message naming the new command. A tombstone that did name it would be a
two-line addition to`Main.hs` per verb; it is not there because C5 ruled against keeping the old
names alive in any form.

**Reading older documents.** Specs, research memos, run reports and blog posts written before
2026-09-24 use the old spellings and are not rewritten: they are records of what was run. Read them
through the table in §1.

## 6. C6 — reasoner backends (OPEN)

`VERIFICATION-BACKEND-LOWERING-SPEC.md` R-V3 names `l4 prove`, which discharges assertions with
Z3; R-V6 has it write SMT-LIB2 text and run a `z3` subprocess.

**Proposed.** `l4 prove` and `l4 verify` stay verbs: they answer a question about the file and
map the answer back onto its source. The artifact a reasoner reads (SMT-LIB2, an UPPAAL model, a
TLA+ module) is additionally reachable as an export format (`l4 export smtlib`), because it is a
foreign notation another tool consumes, and R-V6 already writes it. Not yet ruled.
