The second call is to the people building the next generation of legal technology, and it is an infrastructure pitch: the symbolic half of a neurosymbolic stack, a deterministic core that a language model can call instead of guess.[^1] Large language models write these encodings now. The Axiom Foundation's pipeline reads a statute section by section and has published over 3,000 provisions of US tax and benefit law in its RuleSpec format; its EncodeBench, formalized in July 2026, scores a model on whether an encoding compiles, passes the repository's tests, and contains "zero ungrounded numeric literals: every number in the encoding appears in the source text," across sixteen United Kingdom cases and six models, with the caveat on its own page that "this run is not reasoning-effort matched."[^2] What we add to a model that writes rules is a compiler that refuses ill-typed ones, a gate that no model can pass, and a corpus in which each of those refusals and signatures is on the record.

An L4 file is a poor place for a rule to live, and that is by design. The page that introduces the exports says it: "L4 is where a rule is written down once, precisely. It is rarely where the rule needs to _live_." The benefits agency already runs OpenFisca; the legal-aid charity already publishes docassemble interviews; the bank's analysts already open DMN tables. So L4 compiles out, under two rules — each export is a compiler over a stated subset rather than a converter, and each "would rather refuse than lie."[^3] Here is what compiles out as of 14 September 2026, read from the binary's own help text and the specifications named in the notes. The deployment row is the one a founder would use first. A rule marked `@export` in an L4 file becomes a REST endpoint on a `jl4-service`, either self-hosted or on Legalese Cloud, with a query-plan endpoint that says which inputs still matter; the same deployment is an MCP server that an assistant calls as a typed tool; and a one-line `<script>` tag registers the deployed rules as WebMCP tools on any web page, so a visitor's browser agent can run an eligibility check without scraping the site.[^5] One limit belongs in the body rather than a note: today the HTTP endpoint returns the full evaluation trace on request, and the MCP tool returns the decision alone, with no trace and no citations — the handler calls the evaluator with tracing off.[^5] As `canon` fills, each subject that reaches `reviewed` is a rule set a service can be stood up on; the encodings are Apache-2.0 and the quoted legal text carries whatever terms its jurisdiction attaches.[^8]

Meng's positioning for the interchange rows is that L4 is the spiritual heir of LegalRuleML: a lingua franca for the other rules-as-code languages, with a backlog of exporters still to build.[^6] LegalRuleML is real — an OASIS Standard since 30 August 2021, edited by Palmirani, Governatori, Athan, Boley, Paschke and Wyner — and it was designed as exactly the hub Meng describes. It is also, by its own §2.3, "independent from any legal ontology and logic framework," which is to say it fixes no meaning for its own operators; our research memo of 16 August found every reasoner that ever consumed it dead or unreachable, its technical committee's repository last pushed on 19 July 2020, and its own community transcoding to SPINdle to run anything. Both of those facts held again today.[^6] What the standard got right is its metadata: `LegalSource` and `LegalReference` following Akoma Ntoso's naming, `TemporalCharacteristic` for in-force intervals, and `Alternatives` for competing readings. Those three map onto L4's `@ref` provenance, its `EVAL … UNDER RULES EFFECTIVE AT` clause, and the fork register so closely that the memo calls the match "independent confirmation that L4's annotation layer is designed correctly."[^6] So the heir claim is this: L4 takes the hub role LegalRuleML was built for and adds what the standard never had, an execution semantics and working compilers out. The debt runs the other way too. A LegalRuleML _exporter_ is on the backlog, and the memo's verdict is that it would be a publication-and-provenance artifact rather than an interoperability bridge — roughly 60 percent mechanical, with deadlines, success continuations, parallel composition and traces dropped with a diagnostic because the standard has no place to put them.[^6] No claim of compatibility, round-tripping, or endorsement is made. Akoma Ntoso, the document standard LegalRuleML's references follow — adopted by the Italian Senate in March 2013, an OASIS Standard since 29 August 2018, the base of Brazil's LexML — is already an output: `l4 render --format akn` emits a LegalDocML document today, and the pipeline's own phase script notes that the format is absent from the command's help text and that well-formedness is the only oracle it has.[^7]
