# WHAT "COMPLETED" MEANS ON THESE EIGHT ROWS, AND IT IS LESS THAN IT LOOKS.
# This harness never seeds the variable, so the collection is empty, the
# ForEachNode completes at once, and the instance body NEVER RUNS. Census on
# tenancy-fork.bpmn: StartNode 1x, ForEachNode 1x, EndNode 1x, and nothing else.
# That is a real and useful result — it is the EMPTY CAST executing correctly on
# an independent engine, which is the case the flat drawing got silently wrong —
# but it is not evidence that a member's obligation runs. Do not read it as one.
#
# The body was measured separately, on a scratchpad copy of the harness patched
# only at its startProcess line to seed receipts_cast with three members (repo
# untouched; the technique is in PROCESS-TRACK.md 8.1). Census, tenancy-fork:
#
#   1x  each Tenant [ForEachNode]        the scope itself
#   3x  (unnamed)   [StartNode]          one instance per member
#   3x  MUST Pay ... [HumanTaskNode]
#   3x  MUST Receipt ... [HumanTaskNode] <- the continuation, ONCE PER MEMBER
#   3x  Fulfilled   [EndNode]            each member ends their own instance
#   1x  Fulfilled   [EndNode]            the group, after the last one
#
# Three tenants pay and three receipts are issued. That is UPON EACH, executed.
# Under the flat drawing this branch replaced, MUST Receipt fired once.
#
# OWED, AND NOT A DEFECT IN THE FILE: that seeded run also trips this harness's
# DUPLICATION rule on all four inner nodes, because the rule is "in an acyclic
# process, firing twice means a merge passed tokens through where a join should
# have synchronised". Inside a multi-instance scope, firing once per instance is
# the POINT. The rule already excludes Join nodes and knows nothing about
# ForEachNode scopes. It cannot fire in CI, because CI never seeds — which is
# precisely why it is written down here instead of being left to be rediscovered
# by whoever next patches a harness to seed one.
#
# ALSO FIXED IN THE HARNESS, 2026-09-19: A2 (fanOutEndEvents) appended its clone

# beside its original. No golden's verdict depended on this before the fork

# ADDED 2026-09-19 — tenancy-fork-beside-party.bpmn, a fork beside a PARTY

# It is here as a WITNESS, not for coverage. A fork's breach end must not be an
# error end — an error end ends every active thread in the process, so one
# member's breach would cancel the members who had not breached. The first fix
# demoted the SHARED breach terminal in place, guarded by "only where the fork
# is its sole feeder", which holds on every other fixture in expected/ and
# fails the moment anything else can breach. On this shape the guard did not
# fire and the file kept 409 markings that could complete only by terminating.
# The fork now emits its own EndGroup_<n>/EndBreach_<n>, so this file's shared
# End_3 correctly KEEPS its error end for the landlord's breach (under RAND one
# operand's breach is the whole contract's) while the fork's is plain.
