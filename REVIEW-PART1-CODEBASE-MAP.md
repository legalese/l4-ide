## 1. Big picture

L4 is a layout-sensitive, strongly-typed functional DSL for law (Python-ish indentation, Haskell-ish types), with first-class deontic/regulative constructs (PARTY/MUST/MAY/SHANT/WITHIN/HENCE/LEST) and a lazy evaluator that simulates contracts against event traces. Pipeline:

```
Source (.l4) → Lexer → [PosToken] → Parser (2-pass, mixfix hints) → Module Name
  → ResolveAnnotation (@nlg/@desc attachment) → Desugar (computed fields, inside typecheck)
  → TypeCheck (combined scope+type check, TDNR) → Module Resolved
  → EvaluateLazy (CEK-style lazy machine, IORef thunks) → NF values / contract residuals / traces
```

~27.4k lines of Haskell in `jl4-core/src`. The three giants: `TypeCheck.hs` (3555), `EvaluateLazy/Machine.hs` (3300), `Parser.hs` (2225).

**Two parallel compilation drivers** must stay behaviorally in sync:
- **(A) Shake/LSP driver** — `jl4-lsp/src/LSP/L4/Rules.hs` (a vendored ghcide-style engine on hls-graph). Used by the LSP server, `l4` CLI, `jl4-schema`, jl4-repl, jl4-service, jl4-mlir (all via `LSP.L4.Oneshot`).
- **(B) Pure driver** — `L4.Import.Resolution` + `L4.API.VirtualFS.checkWithImports`. Used by jl4-wasm, `L4.API` (MCP/HTTP/WASM FFI), jl4-actus-analyzer, and jl4-core's own tests. **No caching**; every `L4.API` call recompiles from scratch.

Known divergences between A and B (all part-2 relevant): library shadowing order (LSP: project file overrides embedded lib; pure: embedded always wins — `VirtualFS.hs:99-101` vs `Rules.hs:404-474`); import cycle detection (pure path correct; LSP detects only self/2-cycles — see §7 T2); import evaluation environment (LSP threads dep environments, `Rules.hs:614`; pure path evaluates each import with `mempty` env, `API.hs:328`); entityInfo merge conflicts (LSP `assert`s equality, `Rules.hs:540`; pure path silently left-biases with code that is literally `const`, `Resolution.hs:374`).

## 2. Subsystem guide (what lives where, key invariants)

### 2.1 Lexer & Parser (`L4/Lexer.hs`, `Parser.hs`, `Parser/*`, `Mixfix.hs`)

- Megaparsec lexer emits **trivia as tokens** (whitespace/comments/annotations) — foundation of exact-print. `mkPosTokens` (Lexer.hs:658) converts offsets to `SrcRange` and resolves the ditto token `^` (`TCopy`) against the token at the exact same start column on the previous non-blank line (Lexer.hs:703-708).
- Parser = `ReaderT Env (StateT PState (Parsec Void TokenStream))` over a token stream. **No offside/layout pass**: layout enforced inside combinators (`withIndent`, `manyLines`; Parser.hs:361-407). Expression precedence resolved together with layout in `combine` (Parser.hs:1016-1056): more-indented operators bind tighter; mixed associativity at equal precedence silently right-associates (`Parser.hs:1056`). The `_example1.._example11e` fixtures documenting this algorithm (Parser.hs:1937-2097) are **dead code, never asserted**, and 11a is annotated "This looks wrong".
- **Mixfix** (user operators like ``payer `remits` payee `to settle` ledger``): definition-site extraction (`Mixfix.hs:51-108`) → registry (`Parser/MixfixRegistry.hs`) → **two-pass parsing** (`execProgramParserWithHintPass`, Parser.hs:2195): parse without hints, build registry, re-parse with hints. LSP merges hints from imports. Call sites parse to a flat `App kw [arg, Var kw2, arg...]` that the **type checker** reassembles (TypeCheck.hs:2243-2733). Any mixfix keyword anywhere in scope gates bare-identifier parsing globally (`keywordUniverse`).
- **Span conventions:** `SrcPos` is 1-based (LSP is 0-based; conversions at Rules.hs:812-832). `SrcRange.end` is documented "inclusive" (`SrcSpan.hs:60-61`) but built as position-after-last-char; `inRange` treats end inclusively so adjacent tokens share an in-range boundary. Columns are megaparsec columns (tabs=8, one per Char) — disagree with editor UTF-16 columns on tabs/astral chars.
- NLG annotations are re-lexed/re-parsed by a nested lexer (`execNlgLexer`, Parser.hs:121-185). `@desc` + `@export` share a string-level protocol (`" export" <> t` smuggling, Parser.hs:112-118 ↔ `Export.parseDescText`).
- Post-parse pass `Parser/ResolveAnnotation.hs` attaches `@nlg` (to Name nodes only, with Ambiguous/NotAttached warnings) and `@desc` (leading-line with 8-column slack, or inline). Unclaimed descs produce **no warning** (unlike NLG). `RAction`/`Deonton` instances forgot `extendNlgA` (ResolveAnnotation.hs:508-521).

### 2.2 AST, annotations, exact-print, printing (`Syntax.hs`, `Annotation.hs`, `ExactPrint.hs`, `Print.hs`, `Desugar.hs`, `Transform.hs`)

- Every node: `Anno` as **first constructor field** (enforced by `AnnoFirst` + `gposition @1` deriving-via). Anno payload = interleaving of `AnnoHole` (child placeholder) and `AnnoCsn` (this node's tokens). **Invariant:** hole count/order must match recursive children; **too many holes → `InsufficientHoleFit` error; too few → silent truncation of source text** (`Annotation.hs:211` `go [] _ = pure []`) — the sharpest correctness edge in the subsystem.
- `exactprint` (ExactPrint.hs:40) reproduces source byte-for-byte from annos; golden-tested (218 `.ep.golden` files). `l4 format` is currently the identity via exactprint.
- `Print.hs` (`prettyLayout`) is a separate from-scratch printer that **ignores annos**, un-desugars binops via `Desugar.carameliseNode`, and renders with `Unbounded` layout. It is used as a *protocol* in places (REPL round-trips `prettyLayout` output back through the parser; service codegen; DEONTIC detection by string prefix in LSP document symbols). Known unparseable outputs: `DividedBy` prints `DIVIDED` without `BY` (Print.hs:360); `Exponent` prints `TO THE POWER OF` which has **no surface syntax at all**; `Timezone` decl prints as `mempty` (silently dropped); `Assume`/`Declare` use `fillCat` that can juxtapose GIVEN sig against the keyword with no separator under Unbounded layout (Print.hs:256-263, 204-213).
- `Anno` `Semigroup` with differing ranges **drops the merged `extra`** (type info/nlg/desc) and range (Annotation.hs:328-332). `Extension` merge is left-biased `<|>` per field.
- CBOR `Serialise (Anno_ t e)` encodes any anno as `()` → decodes to `emptyAnno` (`Instances/Serialise.hs:22-24`). jl4-service's `bundle.cbor` persistence therefore erases all ranges, type info, `@desc`, NLG.
- `Desugar.hs` does two unrelated jobs: (1) *caramelise* — inverse of the typechecker's binop→prefix-App rewriting, matched **by rawname text** against builtin names; (2) *computed fields* — pre-typecheck rewrite of field-level `MEANS` into synthetic `DECIDE f _self MEANS e[fields ↦ _self's field]` with SCC cycle detection. `rewriteFieldRefs` does **not** descend into `Event`/`Regulative` (Desugar.hs:356-357) and `patternNames` ignores `PatCons` binders (Desugar.hs:391-394).
- `Transform.hs` (`simplify = cnf . nnf`) — used only by ladder viz; `distr` can blow up exponentially, no guard; discards all annos.
- Two directive filters exist and **contradict** each other on `#TRACE`: AST-based `L4/DirectiveFilter.hs` keeps `Contract` directives; jl4-service's text-based `filterIdeDirectivesText` (`Backend/Jl4.hs:783-831`) strips them.

### 2.3 Type checker (`TypeCheck.hs`, `TypeCheck/*`)

- **Combined scope+type check with TDNR**: `Check a ≅ CheckEnv → CheckState → [(With CheckError a, CheckState)]` — nondeterminism (list) + error accumulation (`With`) + branch-local state. `prune` (Types.hs:799-829) commits to first Plain success; two successes ⇒ `InternalAmbiguityError`; documented quadratic-blowup hazard (Types.hs:793-798). `runCheckUnique` calls Haskell `error` on 0/≥2 results and is reachable from user input via the `Timezone` and `Assert` paths, which use `softprune` (returns all candidates on ties) — see §7 T4.
- **Four phases** (Note [passes], TypeCheck.hs:3508): scan type heads → check type decls → scan term signatures (enables mutual recursion between DECIDEs, mixfix registration) → check bodies. Phase caches keyed **by SrcRange of the Anno**; missing keys throw real exceptions (`fatalInternalError`). Same 3-scan structure replayed for WHERE/LetIn locals.
- All infix operators are desugared at check time into prefix `App`s of builtin names (`__PLUS__` etc.) with careful CSN redistribution (`rewriteBinOpAnno`) so exactprint survives — this is how operator overloading rides TDNR.
- Unification (`Unify.hs`): substitution is `Map Int Type` in branch-local state; occurs check is elem-based; **`unifyBase` recurses with `unify'` not `unify`, and `bind` does `Map.insert` which overwrites** — sibling rebinding soundness hole (§7 T1). Type synonym expansion has no fuel/visited set (mutual synonym recursion → nontermination risk).
- Builtin environment generated by TH (`Environment.hs` `mkBuiltins`; uniques `MkUnique 'b' i builtinUri`). Comparison operators are 3-way overloaded builtins resolved by TDNR.
- CONSIDER exhaustiveness engine (TypeCheck.hs:1669-1917): constructor lookup uses **only the current module's** `declareDeclarations` — imported and builtin types (BOOLEAN/MAYBE/EITHER/LIST) silently get no analysis; `VarEnv` keyed by constructor Unique persists across branches/positions; `isPrimitiveType` matches by name text.
- Deontic typing: `PARTY p MUST action` — action is a *pattern*; its binders scope over PROVIDED and HENCE but **not LEST** (TypeCheck.hs:1126-1127). String literals directly under AND/OR are rewritten to `Inert` nodes (typecheck as identity elements — `setInertContext`, TypeCheck.hs:2891-2955; duplicated logic in Desugar caramelise).
- The reverted **TYPICALLY heisenbug** lived here: `dedupByOrigin`/`allSameTermDescriptor` name-disambiguation where behavior depended on `trace` I/O side effects (see `specs/todo/TYPICALLY-DEFAULTS-SPEC.md`). The buggy code is gone, but the nondeterminism/laziness fragility it exposed in `prune`/TDNR remains architectural.
- IDE artifacts: `infoMap`/`scopeMap`/`nlgMap`/`descMap` (IntervalMaps) + `annInfo` stamped into node Extensions; consumers must `applyFinalSubstitution`. `TypeCheck/Annotation.hs` is actually the NLG-reference resolver, not type-annotation code.

### 2.4 Evaluator (`EvaluateLazy.hs`, `EvaluateLazy/*`, `Evaluate/*`)

- CEK-style machine, `Eval a = EvalState → IO a` (recently flattened from a free monad — commit `eabbd923`; header note Machine.hs:149-160). Exceptions are synchronous IO exceptions caught at directive boundaries (`tryEval`) and in `execEvalModuleWithEnv`. Explicit `IORef` stack (depth cap 1,000,000), ~45 frame constructors.
- Laziness: `IORef Thunk` heap with per-thread blackholing (`atomicModifyIORef'`; same-thread re-entry = `BlackholeForced` loop detection; cross-thread duplication tolerated). `UpdateThunk` frames write back WHNFs. **Nullary builtins (TODAY/NOW/…) deliberately not memoized** because they read the mutable `TemporalContext` (Machine.hs:2322-2333) — but ordinary thunks forced inside `EVAL ... AS OF SYSTEM TIME` scopes ARE memoized with the overridden context and served stale outside (§7 T6).
- Booleans/FULFILLED/EVENT are not primitive — pattern synonyms comparing constructor uniques. Numbers are `Rational` throughout; transcendentals round-trip through `Double` with **no NaN/Infinity checks on `**` and `SQRT`** (`toRational` of NaN → garbage astronomical Rational, silently; Machine.hs:1991, 2065).
- **Contract simulation**: applying a `ValObligation` to `(time, events)` runs the `Contract1..11` frame loop (`backwardContractFrame`, Machine.hs:932-1155). Deadline check is strict `stamp > deadline` (at-deadline is timely). Pattern-match failure of the event action reuses stack unwinding via a `Contract11` guard frame to backtrack to the next event. `RAnd`/`ROr` combine via `RBinOp1/2` with CSL blame assignment (admittedly wrong for out-of-order events, Machine.hs:1104-1106). Known semantic gaps: **the event that reveals deadline expiry is consumed and never offered to HENCE/LEST**; two `ExplicitBreach`es under `ROr` return a residual instead of a breach (§7 T5).
- Temporal context: multi-axis `TemporalContext` in an IORef; scoped overrides via paired frames restoring on the way back. `WHEN LAST`/`WHEN NEXT` iterate day-by-day to year 0 / 9999-12-31 (~740k/2.9M predicate calls worst case). `TIMEZONE IS` handled as order-sensitive module state; a computed timezone string aborts the rest of module decl processing.
- Traces: action log → 5-phase postprocessing (Note in Trace.hs:17-80) with a 10,000-node budget; **multiple bare `error` calls in `splitEvalTraceActions`/`buildEvalPreTrace`** are ErrorCall, not EvalException, so they escape the `try @EvalException` and crash the whole eval (§7 T7). `pushFrame` traces `Push` *before* the depth check.
- `#CHECK` is a **no-op at eval time** (results come from typechecker infos); `#TRACE c AT t WITH events` desugars to applying the contract to the event list. `ToJSON EvalDirectiveResult` always emits `"trace": null`.
- **`DeadlineMissed` ToJSON labels don't match the stored fields** — slot1 is the event's party but is labeled `"deadline"`, etc. (`ValueLazy.hs:306-313` vs construction at Machine.hs:995) (§7 T5).
- JSON encode/decode and constructor special-casing dispatch **by name text** (TRUE/FALSE/NOTHING/JUST/EMPTY/DATE, first name-match in whole EntityInfo) — wrong-module collisions possible. Hand-rolled JSON string escaper misses control chars < 0x20 (Machine.hs:1342-1349). FETCH/POST hand-roll URL parsing; user mistakes surface as "internal error"; HTTP exceptions from `Req.runReq` escape uncaught. `UnaryEnv` reads the real process environment even in safeMode.
- `nf` depth cutoff is 200 (`maximumStackSize`, misleading name) — deep results silently truncate to `Omitted` (→ `null` in JSON).

### 2.5 Driver, imports, exports, schemas (`API.hs`, `Import/Resolution.hs`, `Export*`, `FunctionSchema.hs`, `JsonSchema.hs`, `jl4/app`)

- Embedded stdlib: TH-embedded `jl4-core/libraries/*.l4` (20 libraries incl. prelude, math, daydate, actus family). The TH probe **silently embeds an empty map** if no directory matches (`EmbeddedLibraries.hs:67`).
- `@export`/`@desc`: descs re-parsed by `Export.parseDescText`; exports = explicitly flagged DECIDEs; topmost promoted to default if none marked. Params = GIVEN ⧺ referenced non-function ASSUMEs; optional iff MAYBE-typed. "Implicit ASSUMEs" mined from OutOfScopeErrors (service tolerates them at deploy).
- **Two schema generators diverge**: `L4.FunctionSchema` lowercases type names before matching (correct); `L4.JsonSchema` matches `"Number"`/`"String"`/… against ALL-CAPS builtin names, so **every builtin type emits a dangling `$ref: "#/$defs/NUMBER"`, LIST/MAYBE lose element types, MAYBE fields wrongly required — and the wrong output is enshrined in checked-in `.schema.golden` files** (§7 T3). `FunctionSchema.parametersFromDecideWithErrors` also marks all ASSUME-derived params required, inconsistent with `Export.assumeToParam`.
- `l4` CLI subcommands: run/check/format/ast/batch/trace/state-graph/render (+ separate `jl4-schema` binary). `l4 batch` generates wrapper L4 with an escaper that **only escapes `"` not backslashes** (Batch.hs:234-238) and runs a fresh Shake session per row. `l4 trace` PNG/SVG shells out via `callCommand` with **unquoted interpolated file paths** (Trace.hs:133,137).
- UUID5: two v5 implementations coexist (core's pure SHA1-based in `L4/Crypto`, service uses hackage `uuid`); no cross-check test. Core SHA1's `expandWords` is exponential-ish per block (correct but pathological on large inputs). Document/plan block IDs embed raw Unique numbers — unstable across unrelated edits.
- `L4.Utils.IntervalMap.smallestContaining` ignores its URI argument for filtering and returns length-0 ranges; O(n) per lookup.

### 2.6 Consumers (blast radius of core changes)

- **jl4-lsp is the shared build harness** for CLI/REPL/service/MLIR. Its rule graph (Rules.hs:291-710) is the de facto driver. Fragile contracts: `l4/evalDirectiveResult` matches directives by exact `range.start` equality; `#CHECK` results ride typechecker infos with `severity == SInfo` partitioning; DEONTIC detection by `"DEONTIC" isPrefixOf prettyLayout ty`; semantic-token merging assumes token lengths never change across lexer/parser/typecheck phases; entityInfo union `assert`.
- **jl4-repl** round-trips `prettyLayout (filterIdeDirectives module')` back through the parser for every evaluation — any Print.hs unparseable-output bug (§2.2) breaks the REPL even when the LSP looks fine. Virtual eval files `.repl_eval_N.l4` accumulate for the session.
- **jl4-service** persists `Serialise`'d resolved ASTs (`bundle.cbor`) — core AST shape changes invalidate (gracefully) or **silently misdecode** (if shape-compatible). Direct-AST eval path treats builtin Uniques/refs (`dateUnique`, `nothingRef`…) as a stable ABI. Wire JSON derives from core value printing (`textShow day` = Haskell `Show`!). Deontic values serialize via the mislabeled `DeadlineMissed` JSON (§7 T5).
- **jl4-wasm** re-implements LSP-shaped JSON inside `L4.API` (hand-rolled hover/completions/diagnostics) consumed by `ts-apps/jl4-web/wasm-bridge.ts` — web-vs-VSCode divergence surface. Position conventions inconsistent per function (`l4Hover` converts 0→1-based; `l4Definition`/`l4References`/`l4EvalDirective` don't; API.hs:114 vs 283/709/733).
- **TS side**: `custom-protocol.ts` + Effect schemas in `ts-shared/viz-expr` are hand-mirrored contracts (three implementations of query-plan semantics: Haskell jl4-query-plan, TS boolean-analysis, plus the ladder visualizer's atom-ID matching via UUID5). `ts-shared/l4-highlight` hand-maintains a copy of the lexer keyword tables.
- Public surface of jl4-core (imported outside): Syntax, Annotation, Names, Parser.SrcSpan, Lexer, Parser, Parser.ResolveAnnotation, Citations, Lint.AndOrDepth, TypeCheck(+Types,+Environment), EvaluateLazy(+ValueLazy,+Machine,+Trace,+GraphViz2,+GraphVizOptions), TracePolicy, Print, ExactPrint, Nlg, Desugar, Transform, DirectiveFilter, FindDefinition, FindReferences, Export(+Document,+Render), FunctionSchema, JsonSchema, StateGraph, Viz.Ladder, Viz.VizExpr, API(+VirtualFS,+EmbeddedLibraries), Crypto.UUID5, Utils.IntervalMap, Utils.Ratio, Base*. Internal-only (freer to change): Diagnostic, Mixfix, Parser.Anno, Parser.MixfixRegistry, ParserCombinators, TemporalContext, Import.Resolution, Crypto.SHA1, TypeCheck.{Unify,With,Annotation}, EvaluateLazy.{ContractFrame,Exceptions}, Evaluate.Operators, Utils.RevList.

## 7. Prioritized part-2 target list

Confirmed or high-confidence, in rough severity order. Each was found by static reading in part 1 and needs a repro + fix in part 2.

**T1. Unification soundness — sibling metavariable rebinding.** `Unify.hs:96-122`: `unifyBase` recurses with `unify'` (substitution not consulted mid-walk) and `bind` uses `Map.insert` (overwrites). `Pair a a` vs `Pair NUMBER STRING` likely unifies, silently rebinding `a`. Repro idea: `GIVEN p IS A Pair OF a, a` applied to mixed pair. Related: occurs-check blind spot for intra-call indirect cycles → `ApplySubst` infinite loop (no cycle detection, Types.hs:739-748); recursive/mutual type synonyms have no expansion fuel (Unify.hs:77-91, TypeCheck.hs:1971-1973).

**T2. LSP import-cycle detection broken for cycles ≥ 3.** `LSP/Core/Shake.hs:975-1000` checks only `callstack !! 1 == currentUri` — A→B→C→A never fires; callstack keys grow unboundedly → hang/heap exhaustion in the IDE, service, and CLI (all use pipeline A). Pure path handles cycles correctly. No cycle test exists anywhere. Repro: three files importing in a ring, open in LSP or `l4 check`.
