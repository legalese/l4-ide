# jl4-mlir compiler review

> Adversarial multi-agent review of the L4→MLIR→WASM backend. Generated on branch `mlir-review`.
> Method: 6 subsystem mappers → 18 adversarial claim-verifiers (each trying to _refute_) → synthesis.
> Build/tests ground-truthed locally; the LLVM toolchain was absent, so end-to-end `.l4 → .wasm` execution was not exercised.

## Verdict (3-5 sentences)

The jl4-mlir backend is a real, well-engineered AOT compiler that lowers typed L4 to textual MLIR and on to WebAssembly, with a genuinely exact BigInt-rational numeric core, a total (no catch-all) expression dispatcher, real string builtins, and solid M7 runtime hardening (worker pool, memory caps, timeouts). It builds clean under `-Wall -Werror -Wunused-packages` and all in-repo tests pass. However, its headline guarantees are materially overstated: the most-trumpeted properties — "byte-identical to jl4-service" and "fail loud, never silently degrade" — are refuted by code-level evidence, because parity is verified only by an un-CI'd harness against a ~15-function curated corpus exercised at single degenerate inputs, while several silent wrong-answer paths (string/enum/`PatExpr` CONSIDER always-match, same-arity overload collisions, InfoMap-miss comparisons, MUSTNOT inversion) ship with `supported:true` and no diagnostic. **The single most important caveat: this compiler can return wrong legal/eligibility/compliance answers silently on inputs outside the curated fixture, and nothing in CI can catch it — the "no silent degradation" claim is false in general.**

## What's been done

**Genuinely works in compiled wasm:**

- **Total expression lowering.** `lowerExprCases` (Lower.hs:1468) is an exhaustive case over all 39 `Expr` constructors with no top-level wildcard, so a new AST node is a compile error, not a silent 0.0.
- **Exact-rational NUMBER arithmetic is wired, not dormant.** All of Plus/Minus/Times/DividedBy/Modulo route to `__l4_rat_*` (Lower.hs:1722-1726), literals to `__l4_rat_parse` of exact `num/den` text (Lower.hs:1865), comparisons to `__l4_rat_cmp` (Lower.hs:1997). No `arith.addf/subf/mulf/divf` is emitted by the lowering (`arithAddf` et al. have zero callers in `src/`). The BigInt runtime (jl4-runtime.mjs:2662-2683) is real and unit-tested (rational.test.mjs, 138 assertions, oracle-checked over 20,000 random rationals). This refutes the doc's "slice 2a DONE (dormant) / 2b next" framing — slice 2b has landed.
- **Lambda-lifting / closure conversion** of multi-arg WHERE/LET helpers with explicit capture lists and self/mutual-recursion handling (Lower.hs:2427+).
- **Dual fast/`$trace` codegen** (Lower.hs:1088-1222): a clean untraced hot path plus an instrumented clone.
- **Boolean/pointer box-unbox** via `arith.uitofp`/`cmpf` and bit-preserving `ptrtoint`+`bitcast` roundtrips (Lower.hs:2088-2097, 2287-2301); short-circuit AND/OR via `scf.if`.
- **MLIR pretty-printer** is the most complete piece: correct emitters for every op the lowering produces, UTF-8 byte-length string globals with trailing NUL, IEEE special-value hex literals (Emit.hs:77-94, 590-597).
- **Build/test ground truth:** `cabal build jl4-mlir` compiles with **zero GHC warnings** under `-Wall -Wunused-packages -Werror`; `cabal test` → "All 19 tests passed"; JS suites → rational 138/138, runtime 33/33, backend 6/6. (Caveat: the LLVM toolchain is absent in the verified environment, so end-to-end `.l4 → .wasm` execution was **not** exercised by these commands.)

**Works only via the JS runtime / hand-ported interpreter (not the MLIR compiler):**

- **Strings.** TOUPPER/TOLOWER/TRIM/CONTAINS/SUBSTRING/REPLACE/INDEXOF/concat/len are real JS implementations (jl4-runtime.mjs:2642+), wired through `Lower.hs` runtime calls — README's "string ops stubbed" is stale.
- **Deontic evaluation.** The wasm body for Regulative/Breach is an inert `arith.constant 0.0` (Lower.hs:1839-1840); the MLIR compiler contributes **zero** deontic semantics. A compile-time extractor bakes a `deonticContract` tree into the schema, and a from-scratch JS interpreter (`runDeonticInternal`, jl4-runtime.mjs:530+) replays events. This is a legitimate split capability but is not a "compiler" feature.
- **State graphs / GraphViz strings** are baked at compile time by reusing jl4-core's own `stateGraphToDot` — parity by construction.
- **Trace VALUE rendering** depends on runtime `__forced` markers plus heuristics living in the 4401-line runtime.

**True only on the 12-function fixture (overfit risk):**

- **"11/12 byte-identical" / "20/20 parity."** Verified solely by `parity-harness.mjs` against `test.l4` (12 exports, **one** auto-generated trivial input each — number=1, bool=true, enum[0]) plus 3 deontic fixtures (8 hand-written cases authored to mirror jl4-service's own `TestData.hs`). 3 of the 4 divergence-prone paths (string-pattern CONSIDER, same-arity overloads, cross-module record projection) are **entirely absent** from the corpus; the 4th (NUMBER-returning-call comparison) is mostly defeated by short-circuiting on trivial args.
- **"12/12 trace-byte-identical."** Real for marshaled-arg record projection (genuinely instrumented), but body-allocated records fall to a hardcoded "first field forced" approximation (jl4-runtime.mjs:3722-3737) that the plan itself labels "empirical heuristic, reverse-engineered." A 13th function that projects the _second_ field of a record list is a guaranteed byte mismatch.
- **Shared parameter schema** _is_ genuinely wire-shared with jl4-service (same `L4.FunctionSchema.Parameter` types, Schema.hs:1678-1712) — this part is byte-identical by construction.

## What's left to do

Prioritized by leverage:

1. **Close the silent always-match pattern holes (highest priority — correctness).** String-literal CONSIDER patterns (Lower.hs:2199), `PatExpr` (Lower.hs:2204), and unresolved enum tags (Lower.hs:2174/2185/2190) all return `trueI1` (always match) with `supported:true` and no diagnostic. A working repro exists at `jl4/examples/ok/consider-primitives.l4:20`. Wire `__l4_str_eq` into pattern matching (it already exists) and `markUnsupported` the rest.
2. **Fix deontic semantics or fail loud.** MUSTNOT/prohibition is inverted (a prohibited action done before deadline returns FULFILLED where jl4-core returns BREACH, jl4-runtime.mjs:626 vs Machine.hs:1037-1051); DO≡MUST; PROVIDED guards silently dropped (Schema.hs:801-810 ignores `action.provided`); regulative AND/OR unsupported. Also add the missing null-contract guard on the trace path (jl4-runtime.mjs:3109) so `?trace=full` deontic doesn't silently return FULFILLED.
3. **Same-arity overload collisions.** Arity-only mangling (`name__$arity`, Lower.hs:549) plus `dedupByName` (Lower.hs:633) silently drops all-but-first body for genuine same-arity/different-type overloads. Real corpus example: four `Date` overloads at arity 1 in `daydate.l4`. Disambiguate by type or fail loud.
4. **Exact-number lowering edge:** the InfoMap-miss fallback in `lowerCmp` (Lower.hs:2002-2009) does raw `arith.cmpf` on rational-pool handle bit-patterns — "almost always the wrong truth value" per the code's own comment. Make NUMBER/STRING comparison type-guaranteed, not heuristic.
5. **Fractional decimal input fidelity.** Both host paths force fractional NUMBER inputs through IEEE Double before the exact-rational core sees them (Marshal.hs:85; wasm-server.mjs:239), so `"0.1"` enters as the Double-rounded value (acknowledged at jl4-runtime.mjs:2367).
6. **String-op fidelity:** non-BMP/UTF-16 vs code-point divergence in length/substring/indexOf; `TOSTRING`/`JSON_ENCODE` formatting divergence for small fractions and big integers; missing `SPLIT` builtin entirely.
7. **CLI/runtime gaps:** DEONTIC is unrunnable via CLI (`startTime`/`events` never forwarded, Main.hs:356-361); `--wasmtime`/`--wasmer` are stubs returning "not yet wired"; `supported:false` functions are run anyway with no fallback routing; `-k` keep-intermediate is a no-op; `bundleVersion` is hardcoded `"0.1.0"`.
8. **Broader corpus parity** — nothing samples the ~35 "clean" exportable files beyond the 12-fn fixture; the harness default fixture path is even broken in this worktree.
9. **Toolchain/runtime backends and the Solidity/EVM backend** — the latter is plan-only, zero implementation; its cited "~6-8 weeks" and "6/6 OZ parity" are unvalidated, and it imports a fabricated "56/56" parity figure.

## Design assessment

**Strengths.** The **uniform-f64 ABI** genuinely solves the cross-module/polymorphism SSA-type-mismatch problem: `a -> a` is `f64 -> f64` with no per-call-site monomorphization, and `boxABI`/`unboxABI` are no-ops. The **total `Expr` dispatch** is the strongest possible structural fail-loud guarantee for the expression layer. The **exact-rational ABI** is a principled, well-documented correctness/identity trade-off that matches jl4-core's `Rational` semantics, degrading to Double only at the final marshal exactly where jl4-core also does. The **dual fast/`$trace` path** keeps the hot path instrumentation-free. The **worker-thread pool** is the right architecture for untrusted wasm (terminable infinite loops, bounded memory, fatal/non-fatal classification). Reusing jl4-core's own pure renderers (`stateGraphToDot`, `prettyLayout`) and shared `Parameter` types for the interoperating wire pieces is exactly right.

**Weaknesses.** The biggest tension is **"MLIR as sole engine" vs hybrid reality**: the system is marketed as an MLIR→wasm compiler, but the hardest semantics (deontic evaluation, lazy-NF trace rendering, all string ops) live in a 4401-line JS runtime, and deontic eval is 100% JS over schema JSON with an inert wasm body. Trace and deontic parity are therefore **co-engineered properties of Schema.hs + the runtime against a 12-fn fixture**, not properties of the compiler. The **uniform-f64 ABI is not collision-free**: rational handle, pointer, enum tag, and boolean all share one untagged f64 space (explicitly not NaN-boxing), and handle 0 / null pointer / enum tag 0 / boolean false all collapse to `0x0`; soundness rests entirely on heuristic static-type dispatch, which has documented miss paths. The **"fail-loud" philosophy is real for IO constructs but breached** for patterns and Regulative/Breach. **Dead code misleads**: the entire `BoxKind` machinery in ABI.hs, `Dialect/CF.hs`, `Dialect/MemRef.hs`, `scf.while`, and most `LLVM.hs` struct ops advertise an architecture (cf.switch enum matching, memref storage, struct records) that was abandoned for flat f64 slots. **ABI.hs documentation is aspirational/stale** ("NUMBER is the f64 value directly") and will actively mis-model the system for a maintainer.

## Implementation quality

Code clarity is generally high, with dense, honest inline documentation of heuristics at their point of use — the code rarely hides what it's approximating. The exact-rational core and its oracle-based test (Number(n)/Number(d) over 20,000 random rationals) are the strongest, most rigorous asset in the repo.

**Test coverage is the weak link.** All 19 Haskell tests are `Text.isInfixOf` substring assertions over rendered MLIR/schema text (`isInfixOf` used 58×); **none compiles to wasm, executes a module, or diffs against jl4-service**. Several unit tests assert `arith.addf` appears — but only in hand-built IR, never in lowering output, giving false confidence that float-arith codegen is exercised. The only real byte-identity check is `parity-harness.mjs`, which is **not in CI**, requires the full LLVM toolchain plus a live jl4-service, leaves no committed artifact, has a broken default fixture path in this worktree, and gates only on `differs`+`wasm-error` (so compile-fail, deploy-fail, and even `value-equal` all pass the gate). The **trace machinery is heuristic-laden**: the "first field forced" approximation, `isLikelyParam` (lowercase-no-backtick → param), and `resultKindOf`'s multi-tier fallback all encode prettyprinter-layout assumptions that drift with any Print.hs change. Two analyses that **must stay in lockstep have already drifted**: `Schema.freeVarsOfExpr` drops the App head while `Lower.freeVarsOfExpr` includes it (Schema.hs:660 vs Lower.hs:2531-2536), contradicting the "kept verbatim so they agree" comment — currently masked only because `foldr`/`foldl` are filtered out.

**Build/test ground-truth verdict (confirmed):** _"`cabal build jl4-mlir` compiled all 16 library modules and the executable with ZERO GHC warnings … -Werror genuinely in effect … `cabal test` → All 19 tests passed … node suites all green (33/138/6 pass). SCOPE CAVEAT: the LLVM/MLIR toolchain is absent here, so the true end-to-end .l4 → MLIR → .wasm path is NOT exercised by the verified test commands."_

## Recommendations

Ordered by leverage:

1. **Make CI catch correctness regressions.** Wire a differential parity step into CI (cache a prebuilt jl4-service + LLVM toolchain), commit a parity-report artifact, and **harden the gate** to fail on compile-fail/deploy-fail/`value-equal`, not just `differs`. Without this, every "byte-identical" claim is unverifiable from repo state.
2. **Eliminate the silent always-match paths** (Lower.hs:2199/2204/2174). Wire `__l4_str_eq` into string-pattern matching, compare enum tags or `markUnsupported` on unresolved tags, and test the final WHEN branch instead of running it unconditionally. This is the single highest-correctness, lowest-effort fix.
3. **Fix or fail-loud the deontic interpreter.** At minimum, refuse MUSTNOT/DO/PROVIDED/AND-OR shapes loudly (they currently return wrong answers silently), add the trace-path null-contract guard, and treat `deonticContract:Nothing` as an error on **both** paths. Longer term, derive the interpreter from jl4-core rather than hand-porting a MUST/MAY slice.
4. **Disambiguate overloads by type** (or detect same-arity collisions and `markUnsupported`), so `daydate.l4`-style overloads don't silently drop bodies.
5. **Expand the corpus** beyond the 12-fn fixture: add `.cases.json` with non-degenerate inputs that hit the TRUE branches, sample the ~35 clean exportable files, and add property/fuzz tests for the deontic state machine against jl4-core.
6. **Reconcile the documentation.** Update README (deontic/strings/traces/state-graphs now exist), mark M4 slice 2b DONE, delete the fabricated "56/56", and rewrite ABI.hs to describe the rational-handle reality. Stale docs are currently load-bearing and untrustworthy.
7. **Delete or quarantine dead code** (`BoxKind`, `Dialect/CF`, `Dialect/MemRef`, `scf.while`, unused `LLVM.hs` builders, the `--finalize-memref-to-llvm` pass) so the architecture-on-disk matches the architecture-in-effect.
8. **De-risk numeric/string fidelity:** preserve decimal text into the rational parser (avoid the Double pre-rounding), switch string ops to code-point semantics, add `SPLIT`, and align `TOSTRING`/`JSON_ENCODE` formatters.
9. **Either implement or clearly de-scope** the CLI DEONTIC path, `--wasmtime`/`--wasmer`, and the entire Solidity backend; do not let the EVM plan inherit the WASM backend's unverified parity credibility.
