# feat(ladder): ladder-core and ladder-svg, the IMPLIES seam, guarded rows, and state-graph junctions

**What this adds.** Two new self-contained TypeScript packages — `@repo/ladder-core` (pure `IRExpr → BBE layout → Scene IR`, no DOM) and `@repo/ladder-svg` (Scene IR → SVG, plus the interaction layer) — that draw an L4 boolean decision as a ladder diagram and emit it through four carriers off the same Scene: SVG, ASCII inside a code fence, Mermaid `railroad-beta`, and a plain-prose sentence expansion. The visualiser back end learns three things it could not previously say: `IMPLIES` is kept as a **seam** rather than desugared, so a diagram can distinguish *"you comply"* from *"the rule never reached you"*; guarded chains (`IF/THEN/ELSE`, `BRANCH`, `CONSIDER`) over boolean bodies expand into real ladder structure instead of one opaque box; and `TYPICALLY` presumptions ride the wire IR so the question planner can rank by information gain. On the process side, `l4 state-graph` stops conflating `RAND` with `ROR` (junctions are now explicit `ALL OF` / `ONE OF` diamonds) and stops captioning every `LEST` edge `timeout` regardless of modal. Finally, `GET /ladder` and `POST /query-plan` are made to mint the same `atomId` for the same atom, so a ladder-embedded wizard's answers actually bind.

**Why.** The existing Dagre/SvelteFlow ladder path right-aligns rungs because a general graph engine has no notion of centring, and it renders whole decision tables as a single unreadable ribbon — the R1 corpus spike measured 17 of the 22 widest diagrams in the corpus as single leaves, the worst 4372px wide holding 247 characters of raw L4. Separately, three defects were shipping wrong pictures to readers: a `SHANT`'s `LEST` arm was captioned `timeout`, so seven diagrams in our own examples read *"wait long enough and you are in breach"* (upstream `smucclaw/l4-ide#927`); the two atom-id namespaces meant a client that fetched a diagram and posted answers keyed by its ids got a 200 and a silent no-op (upstream `smucclaw/l4-ide#935`); and a `FALSE` box rendered byte-identically to an `UNKNOWN` one, which is precisely the contrast the two-lamp form needs. The `IMPLIES` work traces the same root cause one level deeper: the classical short-circuit is valid for a truth *value* and wrong for a *verdict*, so the wizard was not merely mislabelling the vacuous case — it stopped the interview with the one distinguishing question unasked.

## What's in it

196 files. Grouped by what a reviewer would want to read together:

**1. `@repo/ladder-core` — the layout kernel (25 files, all new).**
7 source modules: `types.ts`, `layout.ts` (the BBE align-then-stack kernel, where centring is intrinsic rather than a post-pass), `ascii.ts`, `mermaid.ts`, `sentences.ts`, `viz-adapter.ts`, `index.ts`. 12 test files plus one fixture (`test/fixtures/may-purchase-alcohol.viz.json`) captured from a live `jl4-lsp`. `TextMetrics` is injected — Canvas in the browser, headless elsewhere — which is the print-parity keystone. `verdictFor` returns the six-value `Verdict` (`Undetermined | Holds | Fails | Complies | InBreach | NotApplicable`), whose vocabulary is defined once in `@repo/boolean-analysis` and re-exported, so the diagram and the wizard cannot disagree in the same window.

**2. `@repo/ladder-svg` — the rendering backend and the interaction layer (31 files, all new).**
7 source modules: `svg.ts`, `palette.ts`, `controller.ts`, `viewport.ts`, `metrics.ts`, `flip.ts`, `index.ts`. `LadderController` owns the whole DOM half — the `innerHTML` sink, one delegated click on `data-value`/`data-fold` (replacing an O(nodes) per-render re-attach), the `viewBox` pan/zoom, and the FLIP animation, of which exactly one copy now exists in the repo. `viewport.ts` is pure, DOM-free pan/zoom arithmetic. `palette.ts` makes every colour a *parameter* rather than a baked literal, with a source-scan test that fails if a hex literal is ever re-baked into `svg.ts`. Also 7 test files, 5 demos (`s415`, `implies`, `grouping`, `regcf`, `charities-a3`), a corpus-size spike, and `standalone/` — an IDE-free L4→ladder playground whose `serve.mjs` drives a real `jl4-lsp` over websocket and exposes `POST /render {l4}`, so statutes can be rendered headlessly with no SvelteKit, no Monaco and no webview.

**3. The `IMPLIES` seam, end to end (Haskell + wire + TS).**
`L4.Viz.VizExpr.IRExpr` gains `Implies ID IRExpr IRExpr Text`, with `FromJSON` defaulting the seam word so older payloads still parse. Both ladder builders peel the top-level implication **before** `Transform.simplify` runs and simplify each side on its own — simplification is a readability win inside a panel and a shape-destroyer across the seam. `jl4-client-rpc/custom-protocol.ts` gains `Verdict` and `QueryOutcome`, with `determined` kept correct and unchanged beside them. The existing SvelteFlow renderer stays truthful by running `expandImplies` at its single entry point, with a loud throw if an `Implies` ever reaches `transform()` by another route.

**4. Guarded chains as structure — `L4.Viz.GuardedRows` (new, 344 lines).**
A first-match guarded chain over boolean bodies has an exact And/Or reading, so `IF/THEN/ELSE`, `BRANCH` and `CONSIDER` expand into ordinary ladder structure. Deliberately a *shared front end*, not a ladder patch: it is consumed twice today (the core and LSP visualisers carry near-identical `translateExpr` copies over two different `Viz` monads) and carries **rows** rather than a tree so the DMN exporter can read them as decision-table rules. Three bail-outs land on the pre-existing leaf behaviour so nothing gets worse: binding patterns, guards containing `FETCH`/`POST`, and non-boolean result types.

**5. `TYPICALLY` priors on the wire.**
`UBoolVar` gains a sixth `Maybe Bool` field. `boolPriorsFromBody` (Haskell) and `typicallyBridge` (TS) are the two mirrored extractors over that single field, with soft weights `0.9`/`0.1` — soft, never hard `1/0`, so a presumption that would flip the outcome is still surfaced. `robdd.ts` gains `prob`; `decision-query.ts` gains the verdict and the information-gain ranking (`H(scope) + P(scope)·H(req)`), without which the ranking goes blind exactly where the seam fix needs it.

**6. Atom identity.**
`annotateLadderWithAtomIdsUsing` in `LSP/L4/Viz/QueryPlan.hs` rewrites every ladder leaf's `atomId` into the query plan's namespace, from a precomputed map, taking the function name from the caller rather than guessing it off the diagram. The ladder moves onto the planner's namespace and not the reverse: the planner's rendering is the only one of the two that does not embed a compilation-order `unique`, and an `atomId` must survive a redeploy.

**7. State graphs — `L4.StateGraph` (+676 lines) and `jl4-core/test/StateGraphSpec.hs` (new, 465 lines).**
`FanKind` (`Linear`/`AllOf`/`OneOf`) set by `markFan`, so a fan-out finally records whether it is a conjunction or a choice, with associative chains flattened to one n-way junction and junctions drawn as labelled diamonds. `guardedIfBranches` peels an `IF`/`ELSE` chain into a guarded `OneOf` junction, conjoining each arm's condition with the negation of every condition above it. `classifyTarget` gains `TargetSelf` for self-referential `HENCE`. `lestArmWording` derives the `LEST` caption from the modal *and* the deadline (`violation` / `lapses` / `timeout` / `unreachable: no WITHIN`). A structured `BranchGuard`/`GuardAtom` keeps each arm's conjuncts in pieces beside the flattened text, because a consumer that must *resolve* a guard cannot work from `intercalate " AND "`. The 27 `.dot`, 19 `.svg`, 19 `.png` and the README under `jl4/examples/state-graphs/` are regenerated by a committed `regenerate.sh` rather than hand-patched.

**8. Corpus fixtures and goldens (13 `.l4`, 32 `.golden`).**
Five `ok/inert` fixtures move from `jl4/ok/inert/` into `jl4/examples/ok/inert/` — the directory `jl4-test` actually globs, so they had never been under test at all — joined by two that are new relative to `main` (`cheating-415-poh-yuan-nie.l4`, the Poh Yuan Nie [2022] SGCA 74 worked example, and `grounding-variants.l4`), plus `jl4/examples/ok/typically-basic.l4`. Each carries its four goldens (`.golden`, `.ep.golden`, `.nlg.golden`, `.schema.golden`), per `CLAUDE.md` §3.1. `jl4/ok/inert/simple.l4` is deliberately left where it is: its own comment carries an open question, and moving it would newly subject an unresolved question to golden testing.

**9. Three new `jl4` test modules and the IDE-side displayer.**
`VizImplies.hs`, `VizGuardedRows.hs`, `VizAutoRefresh.hs`. On the Svelte side, `l4-ladder-visualizer` gains `LadderSvg` (`ladder-svg.svelte`), the LIR-free `ladder-model.ts`, `sidebar-bridge.ts` and their two test files; `partial-eval-sidebar.svelte` is **reused, not forked** (props widened to a structural `SidebarBindings`; markup and styles byte-unchanged). The displayer is exercised only on `l4-ladder-visualizer`'s own dev route — no file under `ts-apps/` is touched. That package's `eslint.config.js` and `package.json` move with it (the Svelte `generics`-attribute-versus-`no-undef` lint failure #177 diagnosed, and the two new workspace deps).

**10. Editor tokens.** `TYPICALLY` added to the `l4-highlight` keyword set; `•` recognised as an operator in the colorizer and the Monarch grammar.

## Independence

**What this PR genuinely stands on its own for.** The two new packages are self-contained: their only intra-repo dependencies are `@repo/viz-expr` and `@repo/boolean-analysis`, both already on `main`, and they build and test under `tsx --test` with no Haskell build at all. Root `package.json` already globs `ts-shared/*`, so the packages register themselves. The state-graph `.dot`/`.svg`/`.png` artefacts are under no test — #159 measured that nothing in any `.cabal`, `.hs`, CI file or script references that directory — and regenerate from the committed script. `LadderSvg` is exported but mounted only on `l4-ladder-visualizer`'s dev route, so neither IDE app changes behaviour whether or not this lands.

**What it needs from siblings.**

- **ci-build** — `package-lock.json` carries the workspace-link record for `@repo/ladder-core` and `@repo/ladder-svg`. Until it lands, `npm ci` will not link the two new packages (#177 reported that as a two-line lockfile diff, "not lockfile drift").
- **Build metadata in no theme's manifest** — `jl4-core.cabal` needs `L4.Viz.GuardedRows` and `StateGraphSpec`; `jl4.cabal` and `jl4/tests/Main.hs` need `VizImplies`, `VizGuardedRows` and `VizAutoRefresh`. Those files are not listed under any of the 25 themes and must ride with whichever PR carries them, or this one will not compile.
- **service-cli** — the *Haskell* half of the verdict/priors mirror lives there (`jl4-query-plan/src/L4/Decision/BooleanDecisionQuery.hs`, `QueryPlan.hs`, `jl4-service/src/Backend/DecisionQueryPlan.hs`). This PR carries the TypeScript half plus the LSP glue. #110's parity claim is only checkable once both are in, and #210's atom-id fix reconciles a namespace whose other end is defined there.
- **corpus-regcf** — `ts-shared/ladder-svg/test/regcf-figures.test.ts` reads `jl4/examples/legal/regcf/regcf.l4` and `jl4/examples/legal/regcf/figures/*`, and `demo/regcf.ts` renders from the same corpus. Both live in that theme; without it, that one test has nothing to read.
- **lang-syntax-typecheck** — `jl4/examples/ok/typically-basic.l4` needs the `TYPICALLY` lexer/parser/typechecker, and the `•` entries in `colorize.ts`/`monarch.ts` are the editor half of the bullet syntax whose language half lives there.
- **Goldens encode other themes' behaviour, and this is worth saying plainly.** The 32 `.golden` files here are `jl4-test` output — parse, typecheck, evaluate, exact-print, NLG and JSON schema — captured at the tip of `unstable`. They therefore encode the state of the front end (**lang-syntax-typecheck**) and of `L4.Print` (**lang-printer**) as well as this theme's own work. If those land in a different order, expect to re-bless these 32 files; per `CLAUDE.md` §3.1, read them before doing so.

**What needs this PR but is not needed by it.** `L4.StateGraph`'s `BranchGuard`/`GuardAtom` and `FanKind` are defined here and consumed by the BPMN lowering in **bpmn-export** (#198's guarded-gateway → DMN wiring reads exactly those pieces). Nothing in this PR reads them back, so this side is fine alone; bpmn-export is not. Likewise `GuardedRows` carries rows specifically so **dmn-export** can consume them as decision-table rules.

## Risk if rejected

The ladder stops at the picture it draws today: the IDE keeps `expandImplies` at its single entry point and so cannot tell a reader whether a rule bit them or never reached them, a `FALSE` atom keeps drawing as an unanswered one, and decision tables keep rendering as single unreadable ribbons. Three shipped-wrong-picture defects also stay shipped — `SHANT` diagrams that read "wait long enough and you are in breach" (`smucclaw/l4-ide#927`), fan-outs that cannot say conjunction from choice, and the two atom-id namespaces that make a ladder-embedded wizard's answers a silent no-op (`smucclaw/l4-ide#935`) — and **bpmn-export** and **dmn-export** lose the structured branch guards and guarded rows they read.
