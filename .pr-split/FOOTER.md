### About this PR

`unstable` had run 483 commits ahead of `main`. Rather than replay those PRs or raise one
enormous merge, the divergence was re-cut into thematic pull requests, all labelled
`aug2026`, so each can be reviewed, accepted or rejected on its own terms.

The split is a strict partition: all 2,023 changed files are assigned to exactly one PR, with
no file in two of them, and the union reproduces `unstable`'s tree. The five files several
themes genuinely share — four `.cabal` files and `jl4/tests/Main.hs` — were sliced line by line,
so each PR carries only the module registrations its own code needs.

Dependencies between these PRs were **measured, not assumed**: first by resolving every Haskell
import against every sibling's file list and running `npm ci`, and then — once a machine with GHC
was available — by merging candidate sets onto `main` and running `cabal build all`. Import
resolution finds seven edges; building finds an interlock it cannot see at all, because the
entangling changes are to *types* in modules `main` already has. Eight PRs turned out to be
inseparable and were consolidated into **#257**, the language core; what remains below it is a
genuine DAG. Both analyses are recorded in `.pr-split/DEPENDENCIES.md` and `.pr-split/BATCH.md` on
the branch `claude/unstable-branch-reorganization-6cle91`. Every PR states its own position under
**Independence** above.

### Prose and code are in separate PRs — a drift risk to weigh when approving

`partition.mjs` routes by path, and the prose rules (`paper/`, `specs/`, `doc/`) are matched
**before** any feature rule. The consequence is absolute: **no code PR carries a single
documentation file, and the three prose PRs carry no code.** All 251 prose files are in
**#251** (`specs/`, 93), **#237** (`doc/`, 91) and **#248** (`paper/`, 67).

So a feature and its documentation are always in different PRs — `DEONTIC-PARTY-ACTION-AGREEMENT-SPEC.md`
and `TEMPORAL-RULE-VERSION-DESIGN.md` are in #251 while the code they specify is in #257;
`QUESTION-ORDERING-SPEC.md` is in #251 while its code is in #252.

**If approvals do not come as a set, `main` drifts immediately.** Land a prose PR without its code
and `main` documents behaviour it does not have. Land code without its prose and a shipped feature
is undocumented — and for `specs/`, a recorded ruling has no home, which is what this repo's own
`CLAUDE.md` §4 exists to prevent: *"A decision is recorded in its owning document in the same PR, or
it is not decided."*

This is already visible in CI: **#237 cannot go green until #251 and the language core have
landed** — `doc/test-docs.sh` reports 9 broken links, 8 of them pointing at `specs/**` files that
exist only in #251, plus 3 `.l4` examples using `TYPICALLY` and `SET OF`.

Mitigation: land #251, #237 and #248 **last**, and if any code PR is rejected, re-cut the prose PRs
to drop the corresponding pages before they merge.
